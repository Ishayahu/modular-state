# Contributing

This repository is intentionally public because the project needs criticism more than applause.

## Useful contributions

Especially welcome:

- references to existing theories that duplicate part or all of the model;
- peer-reviewed or primary-source criticism of mechanisms used here;
- concrete counterexamples;
- demonstrations that a rule creates incentives not yet considered;
- comparisons with real institutional arrangements;
- corrections to citations or terminology;
- proposals that simplify the model by replacing several special rules with one general rule.

## How to criticise a rule

A strong issue should ideally contain:

1. **Scenario** — a concrete situation.
2. **Target** — which rule or assumption it attacks.
3. **Specificity** — why the problem is caused or worsened by this architecture rather than being a generic human/institutional problem.
4. **Failure mode** — what bad outcome follows.
5. **Comparison** — whether an ordinary state plausibly handles this materially better.
6. **Source** — literature or empirical evidence where available.

## What is not enough by itself

The following are important human problems but are not automatically counterexamples:

- corruption exists;
- courts can err;
- experts can err;
- coups can happen;
- civil wars can happen;
- people can violate rules;
- institutions can become inefficient.

To count as an architectural objection, show that the proposed design systematically worsens the problem or loses a function that a realistic alternative performs materially better.

## Complexity budget

A new counterexample does **not** automatically justify a new constitutional rule.

First try to derive the answer from the existing core.

If a new rule is needed, explain whether it:

- solves a whole class of cases;
- duplicates an existing principle;
- introduces a new failure mode;
- meaningfully increases the complexity of the core model.

The intended core should remain compact.

## Language

Russian is currently the language of record for the canonical working model.

English contributions are welcome. An English canonical translation will be added later after the Russian model stabilises.

## Tone

Attack the model, not contributors.

The project is explicitly interested in reasons why the proposal fails, is already known, is incoherent, or merely moves costs elsewhere.
