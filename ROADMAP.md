# Roadmap

## Phase 0 — Preserve the model

- [x] Create a dedicated public repository.
- [x] Record the current canonical Russian model.
- [x] Record the stress-test / decision history.
- [x] Record open questions.
- [x] Add independent Work red-team prompt.
- [x] Add preliminary related-work map.

## Phase 1 — Independent adversarial research

- [ ] Run the Work prompt against the canonical model.
- [ ] Collect closest prior art.
- [ ] Collect established objections to each component.
- [ ] Identify cases where the current model already answers the objection.
- [ ] Identify cases requiring genuinely new rules.
- [ ] Reassess complexity budget.

Output: `research/work-report-*.md`

## Phase 2 — Reconcile with literature

- [ ] Update `research/related-work.md`.
- [ ] Separate rediscovered mechanisms from potentially distinctive mechanisms.
- [ ] Rewrite the core model where literature exposes failures.
- [ ] Preserve rejected rules and reasons in the decision log rather than silently deleting history.

## Phase 3 — Russian external red-team

- [ ] Prepare a concise Russian 2–4 page note.
- [ ] State explicitly that the goal is criticism, not endorsement.
- [ ] Ask an external political scientist / institutional-design specialist to identify:
  - the closest existing model;
  - fatal or expensive objections;
  - missing literature;
  - points where the model merely shifts costs.

Possible first human target discussed: Ekaterina Schulmann, if a legitimate paid-consultation or collaboration channel is available.

## Phase 4 — Academic abstract

- [ ] Draft Russian abstract.
- [ ] Owner review.
- [ ] Draft English abstract using academic terminology rather than literal translation.
- [ ] Verify all novelty claims against the literature review.
- [ ] Select target venue.

Potential target previously identified: Public Choice Society, subject to current call and attendance constraints at the time of submission.

## Phase 5 — Paper / public critique

- [ ] Expand to a short position paper only after independent criticism.
- [ ] Publish the working paper in the repository.
- [ ] Invite issues / pull requests with concrete counterexamples and citations.
- [ ] Keep a changelog of which objections changed the model.

## Research discipline

A failed model is a useful result.

Do not optimize for preserving the proposal. Optimize for finding whether a compact version survives serious criticism.
